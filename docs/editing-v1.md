# Atomic local editing v1

Optional editing entry returns real Core StatePorts. Authored config is the unchanged BoardDocument; editable state v1 contains document, policyKey, undo and redo document stacks. Selection/viewport/pointer/presence are never part of this state; unknown actions reject. No live renderer or gesture handles are serialized. This issue provides local history, not collaborative undo or a snapshot compatibility adapter.

Actions interactive-project/whiteboard.insert/connect/draw carry object and optional painter index. connect requires connector and draw requires complete freehand. update carries id/changes, replacing complete fields except immutable id/type. extend-stroke appends 1..128 points to a freehand with the document's total/per-stroke bounds. delete carries id. group carries new identity-transform group object and 1..128 IDs with the same existing parent as the new group; this preserves world positions and array painter order. Group transforms can then be changed explicitly. ungroup carries group id and reparents direct children while composing their geometry; nonuniform scale plus child rotation may require unrepresentable shear and is rejected atomically. No shear is silently discarded. Scale/rotation/world limits remain v1 document constraints.

transaction carries 1..64 operations, each with kind plus the relevant fields. Operations work on a private copy; final structural/content/semantic validation happens before one commit. Intermediate references may be repaired in the same transaction. Any rejected operation or final-invalid document leaves Core revision/document/history unchanged. No-op documents reject, so repeated identical updates do not add history. Repeated insert/delete rejects on missing/duplicate identity. Core action sequence and identity enforce transport ordering; a reused old action cannot commit again.

Default cascade deletion removes a group and descendants, or a single object, plus incident connectors. Reject policy leaves deletion dependent on final graph validity, allowing explicit edge/child repairs within transactions. Ungroup retains descendants, removing only the group and (in cascade mode) connectors targeting that group. Undo restores whole prior documents, including stable IDs, connectors, group membership, transforms and painter order; redo restores the subsequent document. New edits after undo clear redo. One transaction is one undo group. undo/redo payloads are empty and reject when unavailable.

History is pure JSON in domain state, bounded to 32 combined entries and 1 MiB of history by default (hosts may tighten). Oldest undo entries are evicted first, then the farthest redo entries. If a previous document itself exceeds the history budget, the edit still commits without retaining that undo. Combined domain state also satisfies Core JSON2 MiB/depth/node limits; histories are evicted until the state fits, otherwise admission rejects. Authored documents that fit standalone but cannot fit the enclosing domain state cannot initialize. Core independently applies its action-string/collection bounds. No externally durable exactly-once identity/history is claimed.

createGestureBuffer is a live host helper for a single bounded gesture (64 operations /64 KiB, tighten only). begin/append/getPreview never mutate Core. cancel/dispose discard previews without history or events. commit consumes the buffer and returns a transaction payload; the host dispatches it with a fresh Protocol Action. A rejected dispatch preserves the board but the consumed gesture must be re-created for retry. Pointer cancellation/disconnect should call cancel; no asynchronous hidden commit occurs.

Headless evaluation remains unevaluable/unassessed. Core lifecycle/interaction emission follows its standard commit boundaries. Snapshot restoration, collaborative causality and rendering are later gates. Existing whiteboard document and shared wire schemas remain unchanged; decision: improvement-proposals/decisions/whiteboard-editing-v1.md.
